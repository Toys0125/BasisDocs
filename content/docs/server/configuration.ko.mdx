### Linux에서 컴파일 및 실행

#### Debian/Ubuntu 요구사항

Ubuntu 22.04:
`sudo add-apt-repository ppa:dotnet/backports`

Debian 또는 기타 특이한 설정:

```
wget https://packages.microsoft.com/config/debian/12/packages-microsoft-prod.deb -O packages-microsoft-prod.deb
sudo dpkg -i packages-microsoft-prod.deb
rm packages-microsoft-prod.deb
```

그런 다음 설치를 계속합니다:

`sudo apt-get update && sudo apt-get install -y dotnet-sdk-10.0`

#### Basis 가져오기

Basis를 다운로드할 디렉토리로 이동하여 다음 명령을 실행합니다:

`git clone -b long-term-support-20260425 https://github.com/BasisVR/Basis`

#### Basis 서버 빌드

새 터미널을 열고 Basis 서버가 포함된 폴더로 cd합니다. 예: `cd Basis/Basis\ Server`

`dotnet restore`

그런 다음 다음으로 빌드합니다:

`dotnet build` (디버그용)

또는

`dotnet build --configuration Release` (릴리스용)

#### 실행

BasisServerConsole 폴더로 이동합니다(예: `/BasisServerConsole/bin/Debug/net10.0/BasisNetworkConsole`)
그리고 실행합니다:

`dotnet .\BasisNetworkConsole.dll`

## 방화벽

다음 포트를 열어야 할 수 있습니다:
 * 1234/tcp
 * 10666/tcp
 * 4296/udp

## 구성 파일

서버를 처음 실행하면 서버 exe가 있는 폴더에 여러 구성 파일과 구조가 생성됩니다.

| 파일/폴더                | 설명                                        |
|--------------------------|---------------------------------------------|
| `config.xml`             | 서버의 기본 구성 파일.                       |
| `initialresources/`      | 이 폴더에는 서버가 요청 시 로드하는 월드 및 오브젝트 파일이 포함됩니다. |
| `Log/`                   | 서버 로그가 저장되는 폴더.                   |
| `admins.xml`             | 관리자 권한이 있는 사용자 목록.             |
| `banned_players.xml`     | 차단된 플레이어 계정 목록.                  |

## Config.xml

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PeerLimit` | 65535 | 연결된 peer의 최대 수입니다. |
| `SetPort` | 4296 | 서버가 수신 대기하는 UDP 포트입니다. |
| `UseNativeSockets` | true | 관리 경로 대신 운영체제 네이티브 socket 호출을 사용합니다. |
| `NatPunchEnabled` | false | peer 소개를 위한 NAT punch-through를 활성화합니다. |
| `PingInterval` | 1500 | keep-alive ping 간격(밀리초)입니다. |
| `DisconnectTimeout` | 30000 | 응답이 없는 peer를 연결 해제하기까지의 시간(밀리초)입니다. |
| `SimulatePacketLoss` | false | 테스트를 위해 송신 패킷을 인위적으로 폐기합니다. |
| `SimulateLatency` | false | 테스트를 위해 패킷을 인위적으로 지연시킵니다. |
| `SimulationPacketLossChance` | 10 | 패킷 손실 시뮬레이션이 활성화되었을 때의 손실 비율입니다. |
| `SimulationMinLatency` | 50 | 추가되는 최소 지연 시간(밀리초)입니다. |
| `SimulationMaxLatency` | 150 | 추가되는 최대 지연 시간(밀리초)입니다. |
| `ReconnectDelay` | 500 | 재연결을 시도하기 전 대기 시간입니다. |
| `MaxConnectAttempts` | 10 | 최대 연결 시도 횟수입니다. |
| `ReuseAddresss` | false | socket 재사용 옵션입니다. 필드 철자에 주의하세요. |
| `DontRoute` | false | socket 라우팅 옵션입니다. |
| `EnableStatistics` | true | health/status 보고를 위한 전송 통계를 수집합니다. |
| `IPv6Enabled` | true | IPv6 dual-stack socket 지원을 활성화합니다. |
| `MtuOverride` | 0 | 고정 MTU를 강제합니다. 0은 덮어쓰기를 비활성화합니다. |
| `MtuDiscovery` | true | Path-MTU discovery를 활성화합니다. |
| `DisconnectOnUnreachable` | false | ICMP unreachable 수신 시 연결을 끊습니다. |
| `AllowPeerAddressChange` | true | 세션 중 peer endpoint 변경을 허용합니다. |
| `HasFileSupport` | true | 로그, moderation 목록, auth ID 데이터 및 기타 디스크 기반 데이터 쓰기를 활성화합니다. |
| `HealthCheckHost` | localhost | health check용 호스트 또는 인터페이스입니다. *는 모든 인터페이스에 바인딩합니다. |
| `HealthCheckPort` | 10666 | health check용 TCP 포트입니다. |
| `HealthPath` | /health | health check endpoint 경로입니다. |
| `BSRSMillisecondDefaultInterval` | 50 | Server Reduction System의 기본 전송 간격(밀리초)입니다. |
| `BSRBaseMultiplier` | 1 | 거리 스케일링 전에 적용되는 기본 배율입니다. |
| `BSRSIncreaseRate` | 0.005 | 거리에 따라 전송 간격이 증가하는 속도입니다. |
| `BSRSlowestSendRate` | 2.55 | 멀리 있는 peer에 대해 클라이언트에 전달되는 가장 느린 전송 속도입니다. |
| `HighQualityDistance` | 3 | 고품질 avatar 동기화 거리 임계값입니다. |
| `MediumQualityDistance` | 10 | 중간 품질 avatar 동기화 거리 임계값입니다. |
| `LowQualityDistance` | 20 | 저품질 avatar 동기화 거리 임계값입니다. |
| `OverrideAutoDiscoveryOfIpv` | false | IP 버전 자동 감지 대신 설정된 주소에 정확히 바인딩합니다. |
| `IPv4Address` | 0.0.0.0 | IPv4 바인딩 주소입니다. |
| `IPv6Address` | :: | IPv6 바인딩 주소입니다. |
| `Password` | default_password | 서버 접근 비밀번호입니다. |
| `UseAuth` | true | 비밀번호 인증을 활성화하거나 비활성화합니다. |
| `UseAuthIdentity` | true | auth가 활성화되면 DID ID 검증을 요구합니다. |
| `BasisUserRestrictionMode` | Normal | 입장 제한 모드: Normal, BlackList 또는 WhiteList. |
| `HowManyDuplicateAuthCanExist` | 2 | 동일한 auth ID에 허용되는 동시 연결 수입니다. |
| `AuthValidationTimeOutMiliseconds` | 9000 | auth 검증 제한 시간(밀리초)입니다. |
| `EnableConsole` | true | 대화형 서버 콘솔을 활성화합니다. |
| `DisableWriteUnlessAdminPersistentFlag` | true | 호출자가 admin이 아니면 persistent key/value 쓰기를 거부합니다. |
| `DisableReadUnlessAdminPersistentFlag` | false | 호출자가 admin이 아니면 persistent key/value 읽기를 거부합니다. |
| `UseNetworkFinalCompression` | false | 최종 네트워크 압축 단계를 활성화합니다. |
| `EnableBSRProfiling` | false | Server Reduction System profiling 출력을 냅니다. |
| `DisallowHeadless` | false | 연결 시 headless 클라이언트를 거부합니다. |
| `AvatarsLocked` | false | bypass 권한이 없는 사용자의 avatar 로드를 차단합니다. |
| `PropsLocked` | false | bypass 권한이 없는 사용자의 prop 로드를 차단합니다. |
| `WorldsLocked` | true | bypass 권한이 없는 사용자의 world 로드를 차단합니다. |

<small>공개 구성 필드와 이름이 일치하는 환경 변수는 시작 시 해당 필드를 덮어씁니다.</small>

## 로드 가능한 구성 파일

요청 시 로드할 월드 및 오브젝트 파일을 설정할 수 있습니다.
이것들은 `InitialResources` 폴더에 넣는 파일들입니다.

<Callout type="warn">
사용하는 외부 URL은 청킹을 지원하는 적절한 서버에서 제공되어야 합니다.
모든 최신 서버는 이를 지원해야 하지만, 간단한 로컬 개발 서버는 지원하지 않을 수 있습니다.
</Callout>

<Callout type="info" title="무언가 로드하기">
새 씬을 테스트하는 한 가지 방법은 Unity에서 씬을 만들고 BEE 파일로 내보내는 것입니다. 해당 BEE 파일을 HTTP를 지원하는 서버에 업로드한 후, URL을 `CombinedURL`에 입력하고 `dontuploadmepassword.txt`에서 비밀번호를 가져와 `UnlockPassword`에 입력합니다.
</Callout>

| 변수             | 정의 |
|------------------|------------|
| `Mode`           | 구성 모드: `0` = 게임 오브젝트, `1` = 씬. |
| `LoadedNetID`    | 네트워크 ID: 서버는 클라이언트가 이 값을 참조로 쿼리하고 스폰할 수 있는 네트워크 오브젝트 목록을 유지합니다. |
| `UnlockPassword` | 리소스를 잠금 해제하거나 접근하는 데 필요한 비밀번호. |
| `CombinedURL`    | `.BEE` 파일의 URL |
| `IsLocalLoad`    | 리소스가 로컬(`true`)에서 로드되는지 인터넷(`false`)에서 로드되는지 나타냅니다. |
| `PositionX`      | 오브젝트의 X축 월드 위치. |
| `PositionY`      | 오브젝트의 Y축 월드 위치. |
| `PositionZ`      | 오브젝트의 Z축 월드 위치. |
| `QuaternionX`    | 오브젝트 회전의 X 성분(쿼터니언). |
| `QuaternionY`    | 오브젝트 회전의 Y 성분(쿼터니언). |
| `QuaternionZ`    | 오브젝트 회전의 Z 성분(쿼터니언). |
| `QuaternionW`    | 오브젝트 회전의 W 성분(쿼터니언). |
| `ScaleX`         | X축 스케일 팩터. |
| `ScaleY`         | Y축 스케일 팩터. |
| `ScaleZ`         | Z축 스케일 팩터. |
| `Persist`        | 오브젝트를 스폰한 플레이어가 서버를 떠나도 오브젝트가 계속 존재하나요? |

### 예시 구성

```xml title="BasisLoadableConfiguration-예시"
<BasisLoadableConfiguration>

    <!-- Mode of the configuration: Mode  0 = Game object, 1 = Scene -->
    <Mode>0</Mode>

    <!-- A Network ID: Server keeps a list of Network Objects that Clients can query and spawn with this value. -->
    <LoadedNetID></LoadedNetID>

    <!-- Unlock password -->
    <UnlockPassword>ffee4439eff</UnlockPassword>

    <!-- Combined URL link to BEE file -->
    <CombinedURL>https://www.example.com/2lkj23j.BEE</CombinedURL>

    <!-- Does this resource exist on the internet or in the client? -->
    <IsLocalLoad>false</IsLocalLoad>

    <!-- Position values -->
    <PositionX>0</PositionX>
    <PositionY>0</PositionY>
    <PositionZ>0</PositionZ>

    <!-- Quaternion values -->
    <QuaternionX>0</QuaternionX>
    <QuaternionY>0</QuaternionY>
    <QuaternionZ>0</QuaternionZ>
    <QuaternionW>1</QuaternionW>

    <!-- Scale values -->
    <ScaleX>1</ScaleX>
    <ScaleY>1</ScaleY>
    <ScaleZ>1</ScaleZ>

    <!--  If the player that spawned the object leaves the server does the object continue to exist?  -->
    <Persist>false</Persist>

</BasisLoadableConfiguration>
```
